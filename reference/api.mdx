Gainable is reached from code and other tools through **MCP**, the open standard AI tools use to connect to other systems. There are two, for two different jobs:

- **The app's MCP** is how you work with one app's data: ask about it, add and update records, hand it recurring work. Every app has its own, reached through its [shared Assistant](/manage/share-assistant).
- **The Gaia MCP connector** is for building: create, change, publish and share apps, manage datasets, and write an app's code.

Each app's own REST API serves the app's pages and isn't open to outside callers.

## Choose the right way in

| You want to | Use |
| --- | --- |
| Ask about an app's data, add or update its records, or give it recurring work, from ChatGPT, Claude or another AI tool | **The app's MCP**: [share its Assistant](/manage/share-assistant), then [add it to your AI tool](/use/ai-tools) |
| Build, change, publish or share apps from an AI tool | **The Gaia MCP connector**: [overview](/mcp/overview) |
| Write an app's code yourself | **The Gaia MCP connector** in [author mode](/mcp/tools#author-mode) |
| Build or sync from a script, a CI job or a server, with no person signing in | **The Gaia MCP connector** with an [account API key](/mcp/api-keys) |
| Keep a dataset filled from a source Gainable has no connector for | **The Gaia MCP connector**: [Bring any source](/data/any-source), with the `dataset_sync` tool |

Both follow the same access rules as the builder and the app: a person reaches only the records they're allowed to see, and an API key acts for your account, never past it.

## Run on a schedule

Recurring work on an app's data doesn't need a server of your own. Pick the way that fits where the work happens:

| The work | Run it with |
| --- | --- |
| Uses the app's data and the tools its Assistant already has | The Assistant's own [scheduled tasks](/manage/assistant#scheduled-tasks), which run in Gainable |
| Uses the app's data alongside your other connectors, such as email | A [scheduled task in a Claude project](/use/ai-tools#make-it-part-of-your-work) with the app's MCP connected |
| Runs next to something private, such as a local database or a VPN | A local MCP client with the app's MCP added, started by cron or Task Scheduler |
| Brings data in from another system, with no person involved | A collector that pushes to the app's dataset with `dataset_sync` and an [account API key](/mcp/api-keys). See [Bring any source](/data/any-source) |

The app's MCP always acts as a person. Each client signs in once in the browser with that person's Gainable account, and keeps the connection alive on its own while it is used at least every 90 days. The connection ends when the app's owner turns sharing off or the person loses access to the app. A sign-in made in one AI tool can't be reused by another: each client signs in for itself.

Account API keys don't open an app's MCP. They are for the Gaia MCP connector, which reaches the app's data only through its dataset.

## The app's own API

Every app has a REST API that its pages use to read and save records, and a real-time channel that keeps everyone's screen current. Both belong to the app itself. Requests from outside the app's own pages are refused, and there are no keys or tokens for calling them from elsewhere.

To work with an app's data from code or an AI tool, use **the app's MCP**. It works with the same data and follows the same access rules.
