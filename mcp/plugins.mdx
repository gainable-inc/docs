The connector works on its own, but in Claude Code, Cowork and Codex you can install the **Gainable plugin** instead. One install brings two things:

- **The connector**, already registered at `https://build.gainable.dev/mcp`. You sign in on first use.
- **The Gainable skill**, guidance your agent reads before its first turn: which tool fits which request, how to relay Gaia's questions to you instead of answering them itself, and how to keep track of which app a folder belongs to.

<Tabs>
  <Tab title="Claude Code">
    ```
    /plugin marketplace add gainable-inc/plugins
    /plugin install gainable@gainable
    ```

    Restart Claude Code, then run `/mcp` to sign in.
  </Tab>
  <Tab title="Cowork">
    Select **Customize** in the sidebar, then **Plugins** → **Add marketplace**, enter `gainable-inc/plugins`, and select **Install**. You're asked to sign in to Gainable, because the plugin brings the connector.
  </Tab>
  <Tab title="Codex">
    ```
    /plugin marketplace add https://github.com/gainable-inc/plugins
    /plugin install gainable
    ```

    You sign in on first use. Codex asks you to trust the plugin's session hook before it runs.
  </Tab>
  <Tab title="Claude chat">
    Plugins aren't used in Claude chat, so the guidance comes as a skill instead. Download `skill/gainable-skill.zip` from the [gainable-inc/plugins](https://github.com/gainable-inc/plugins) repository, then at [claude.ai/customize/skills](https://claude.ai/customize/skills) select **+** → **Create skill** → **Upload a skill**, and check that its toggle is on.

    The skill carries the guidance only. Add the connector separately. See [Claude and Cowork](/mcp/claude).
  </Tab>
</Tabs>

## Choosing what it can do

When you sign in, the consent screen has three optional checkboxes. All three are off by default, and building, changing, publishing and sharing apps, including building from a spreadsheet, work without any of them:

| Checkbox | Adds |
|----------|------|
| *Also let it write code in your apps* | [Author mode](/mcp/tools#author-mode): `code_context` and `code_push` |
| *Also let it work with your datasets* | `dataset_list`, `dataset_records`, `dataset_schema`, `dataset_sync`, `dataset_delete` |
| *Also let it add and manage people on the account* | `account_users`. Offered only to someone who can already manage users. |

Change them later at [Account → Connections](https://build.gainable.dev/account/connections), without reconnecting. A tool that's missing is almost always a box that isn't ticked.

## If the tools appear twice

If you also added Gainable as a connector on your claude.ai account, Claude Code and Cowork show both: the plugin's connection and the account's. The tools then appear twice under different names, and the skill can't tell them apart from a real pair of accounts, so it asks which one to use before every build. Turn one of them off.

## Connecting to another instance

The plugin points at `https://build.gainable.dev/mcp`. In Claude Code and Cowork, set `GAINABLE_MCP_URL` before starting a session to point it somewhere else:

```bash
GAINABLE_MCP_URL=https://staging-build.gainable.dev/mcp claude
```

To keep production connected alongside, add the other instance as a second server instead. The skill applies to it too:

```bash
claude mcp add --transport http gainable-staging https://staging-build.gainable.dev/mcp
```
